# Linux 系统安装、分区与挂载

本章介绍在虚拟机中安装 Linux 时的基础概念，以及磁盘分区、文件系统和挂载之间的关系。

## 1. 使用 VMware 虚拟机

虚拟机（Virtual Machine，VM）是在一台物理计算机上运行的“模拟计算机”。它可以让一台主机同时运行多个操作系统，例如在 Windows 中运行 Linux。

### 1.1 虚拟机的优点

- 可以在一台电脑中运行多个操作系统。
- 虚拟机通常可以通过主机的网络访问互联网。
- CPU、内存、磁盘、网卡等硬件资源可按需调整。
- 适合练习安装、分区、网络配置等操作，不会直接影响真实主机。
- 可以使用快照快速回到某个可用状态。

> Windows 现在可通过 WSL（Windows Subsystem for Linux）使用 Linux 环境；但若要学习完整的系统安装、磁盘分区和硬件配置，虚拟机通常更合适。

### 1.2 软件与安装位置建议

服务器软件并非越新越好。较成熟的稳定版本往往 Bug 更少、系统要求更低，也更便于长期维护。

在 Windows 主机上安装虚拟机软件时，建议不要把大量应用程序或虚拟机文件都放在系统盘（通常是 `C:`）。原因如下：

- 为系统盘保留足够空间，可降低系统更新或故障恢复时的风险。
- 将虚拟机文件放在数据盘（如 `D:`）中，重装系统后更容易保留和重新使用数据。
- 为每台虚拟机建立独立目录；不再使用时，删除该目录即可，便于管理。

### 1.3 创建虚拟机的建议

学习阶段建议先创建一块**空白虚拟磁盘**，再手动安装操作系统和进行分区。这样可以理解每一步的作用，避免完全依赖自动化安装。

创建虚拟机时可注意以下资源配置：

| 项目 | 建议 |
| --- | --- |
| 虚拟磁盘 | 可设置最大容量（例如 20 GB）。动态分配磁盘通常只会随实际使用逐步占用主机空间。 |
| 内存 | 不应超过主机可用内存；为主机保留足够资源，避免主机和虚拟机同时卡顿。 |
| CPU | 虚拟 CPU 数量不应超过主机的逻辑 CPU 数量，并应为主机保留资源。 |
| 安装介质 | 在虚拟光驱中选择 Linux ISO 镜像，并启用“启动时连接”。 |
| 网卡 | 根据练习目标选择 NAT、桥接或仅主机网络模式。 |

### 1.4 快照与克隆

#### 快照（Snapshot）

快照会记录虚拟机在某个时间点的状态。配置实验或升级前创建快照，出现问题后可恢复到该状态。

> 快照会消耗额外磁盘空间；不应长期大量保留。真实物理机通常没有这种一键快照能力。

#### 克隆（Clone）

克隆用于复制一台虚拟机。

- **链接克隆**：与原虚拟机共享部分基础磁盘文件，占用空间较少；原虚拟机或其文件缺失时，链接克隆可能无法正常运行。
- **完整克隆**：复制出独立的虚拟机文件，占用空间较多，但不依赖原虚拟机。

## 2. 磁盘分区与文件系统

### 2.1 为什么要分区

可以把一块完整磁盘理解为一个大柜子，分区则是把大柜子划分为多个小柜子。每个分区可以独立格式化、挂载和管理。

分区常用于：

- 将系统、用户数据和备份数据分开管理。
- 为不同用途选择不同的文件系统或挂载选项。
- 在重装系统时尽可能保留独立的数据分区。

### 2.2 分区、格式化与挂载的关系

这三个步骤容易混淆，顺序通常如下：

1. **分区（Partition）**：在磁盘上划分出一个或多个逻辑区域。
2. **格式化／创建文件系统（Format / Make filesystem）**：在分区上创建 `ext4`、XFS、Btrfs 等文件系统。
3. **挂载（Mount）**：把已有文件系统连接到 Linux 的目录树中，供用户和程序访问。

> 挂载不是格式化。格式化会创建文件系统；挂载只是让操作系统在某个目录中访问已有文件系统。

### 2.3 文件系统的基本工作

文件系统负责在分区中组织和查找文件。以常见 Linux 文件系统为例，它主要会：

1. 将存储空间按固定大小划分为数据块（例如 4 KiB）。
2. 为文件和目录保存元数据；在许多 Linux 文件系统中，这些元数据由 inode（索引节点）表示。
3. 记录数据块的使用情况和文件目录结构，以便根据文件名定位 inode，再读取对应的数据块。

inode 通常保存文件类型、权限、所有者、时间戳及数据位置等信息；文件名与 inode 的对应关系由目录保存。

### 2.4 Linux 设备文件名

Linux 内核会把硬盘和分区表示为 `/dev` 目录下的**设备节点**（device nodes）。它们是访问设备驱动的接口，不是普通数据文件。

常见示例：

| 设备 | 含义 |
| --- | --- |
| `/dev/sda` | 一块 SATA/SCSI/USB 磁盘（名称会因硬件环境而异） |
| `/dev/sda1` | `/dev/sda` 的第一个分区 |
| `/dev/nvme0n1` | 一块 NVMe 磁盘 |
| `/dev/nvme0n1p1` | 该 NVMe 磁盘的第一个分区 |

可使用下列命令查看磁盘、分区和文件系统：

```bash
lsblk -f
```

## 3. 挂载文件系统

Linux 使用统一的目录树。一个分区或其他存储设备必须挂载到某个目录（称为**挂载点**）后，才能通过该目录访问其中的文件。

例如，将 `/dev/sda1` 挂载到 `/mnt/data` 后，访问 `/mnt/data` 实际上就是访问 `/dev/sda1` 中的文件系统。

### 3.1 `mount` 命令格式

```bash
mount [-t 文件系统类型] [-o 挂载选项] 设备文件名 挂载点
```

参数说明：

| 参数 | 说明 |
| --- | --- |
| `-t` | 指定文件系统类型，例如 `ext4`、`xfs`、`btrfs`。许多情况下可由系统自动识别。 |
| `-o` | 指定挂载选项，例如 `rw`、`ro`、`noexec`、`nosuid`。多个选项以逗号分隔。 |
| 设备文件名 | 要挂载的设备或分区，例如 `/dev/sda1`。 |
| 挂载点 | 用于访问该文件系统的已有目录，例如 `/mnt/data`。 |

### 3.2 挂载示例

先创建挂载点，再进行挂载：

```bash
sudo mkdir -p /mnt/data
sudo mount -t ext4 -o rw,noexec,nosuid /dev/sda1 /mnt/data
```

查看当前挂载状态：

```bash
findmnt /mnt/data
df -hT /mnt/data
```

卸载时，确保没有程序正在使用该目录：

```bash
sudo umount /mnt/data
```

> 以上命令中的 `/dev/sda1` 仅为示例。执行格式化、挂载或卸载操作前，请用 `lsblk -f` 确认目标设备，避免操作到错误分区。

## 4. Linux 与 Windows 的磁盘访问方式

Windows 和 Linux 都能识别硬盘及其分区，只是向用户呈现的方式不同。

| 系统 | 常见访问方式 |
| --- | --- |
| Windows | 通常以盘符显示，例如 `C:`、`D:`；底层同样存在设备和卷标识，只是一般不直接展示给普通用户。 |
| Linux | 通过 `/dev` 下的设备节点表示设备，并将文件系统挂载到统一目录树的某个目录。 |

因此，Linux 中“挂载”是将文件系统接入目录树的必要操作；Windows 则通常自动完成类似的连接，并以盘符的形式呈现给用户。

## 5. 小结

- 分区是在磁盘上划分存储区域。
- 格式化是在分区上创建文件系统。
- 挂载是将文件系统连接到 Linux 目录树。
- `/dev/sda1` 等是设备节点；`/mnt/data` 等是挂载点。
- 虚拟机适合练习 Linux 安装、分区和系统管理操作；快照与克隆可帮助快速回滚或复制实验环境。
